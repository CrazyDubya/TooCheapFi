# TooCheapFi v1.5 Plan - CI/CD Fixes

## Overview
v1.5 focuses on fixing CI/CD to ensure all GitHub Actions workflows pass successfully.

## Identified Issues

### 1. Package Structure Issue (Critical)
**Problem**: Tests cannot import the executable target `TooCheapFi`

The current Package.swift has:
- An executable target `TooCheapFi` (Sources/)
- A test target `TooCheapFiTests` (Tests/) with NO dependencies

Test files reference types like `AppConstants`, `formatDuration()`, `ConnectionQuality` etc. but don't import any module. Swift Package Manager doesn't allow importing executable targets into tests.

**Solution**: Restructure into Library + Executable pattern:
```swift
targets: [
    .target(
        name: "TooCheapFiCore",  // Library with all code
        path: "Sources",
        exclude: ["main.swift"]
    ),
    .executableTarget(
        name: "TooCheapFi",      // Thin executable
        dependencies: ["TooCheapFiCore"],
        path: "Sources",
        sources: ["main.swift"]
    ),
    .testTarget(
        name: "TooCheapFiTests",
        dependencies: ["TooCheapFiCore"],  // Can now import
        path: "Tests"
    )
]
```

### 2. Missing Test Imports
**Problem**: All test files are missing `@testable import`

**Files needing update**:
- Tests/PreferencesTests.swift
- Tests/QualityScoreTests.swift
- Tests/SignalQualityTests.swift
- Tests/EventHooksTests.swift
- Tests/HistoryStoreTests.swift
- Tests/ConnectivityCheckerTests.swift
- Tests/WiFiAnalyzerTests.swift
- Tests/UtilitiesTests.swift
- Tests/AppConstantsTests.swift
- Tests/LoggerTests.swift

**Fix**: Add to each file:
```swift

```

### 3. SwiftLint Configuration for Tests
**Problem**: Tests might fail linting due to rules not suitable for test code

**Fix**: Adjust `.swiftlint.yml` to be more lenient on test files:
- Allow longer functions in tests
- Allow more parameters in test assertions
- Exclude certain rules for Tests/

### 4. Coverage Generation
**Problem**: Coverage export command assumes specific paths that might not exist

**Current command**:
```bash
XCTEST_PATH=$(find .build -name "*.xctest" -type d | head -1)
```

**Fix**: Add error handling and fallback for coverage generation

### 5. Protocols Directory Not in Package
**Problem**: New `Sources/Protocols/` directory needs explicit inclusion

The Package.swift uses `path: "Sources"` which should include subdirectories, but we should verify.

## Detailed Changes

### Package.swift (New)
```swift
// swift-tools-version: 5.9
import PackageDescription

let package = Package(
    name: "TooCheapFi",
    platforms: [
        .macOS(.v12)
    ],
    products: [
        .executable(
            name: "TooCheapFi",
            targets: ["TooCheapFi"]
        ),
        .library(
            name: "TooCheapFiCore",
            targets: ["TooCheapFiCore"]
        )
    ],
    targets: [
        .target(
            name: "TooCheapFiCore",
            path: "Sources",
            exclude: ["main.swift"],
            sources: nil  // All .swift files except main.swift
        ),
        .executableTarget(
            name: "TooCheapFi",
            dependencies: ["TooCheapFiCore"],
            path: "Sources",
            sources: ["main.swift"]
        ),
        .testTarget(
            name: "TooCheapFiTests",
            dependencies: ["TooCheapFiCore"],
            path: "Tests"
        )
    ]
)
```

## Alternative Approach (Simpler)

If the Library+Executable pattern causes issues, an alternative:

1. Keep executable target as-is
2. Change tests to NOT import the module
3. Tests only test logic that can be copy-pasted or re-implemented

However, this defeats the purpose of unit testing. The Library+Executable pattern is the correct Swift approach.
