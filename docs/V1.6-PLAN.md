# TooCheapFi v1.6 Plan - Public API & Test Infrastructure

## Overview
v1.6 addresses the fundamental issue that the TooCheapFiCore library has **no public API**. All types are internal by default, making the library unusable and forcing tests to reimplement logic.

## Critical Issues

### 1. No Public API (BLOCKING)
Every type, function, and class in the library is `internal` by default. This means:
- External consumers cannot use TooCheapFiCore
- Tests rely on `@testable import` hack
- The "library" isn't actually a library

### 2. Tests Duplicate Production Logic
Current test files define private helper functions that *mirror* production code:
- `QualityScoreTests` reimplements `qualityFromScore()`, `signalPenalty()`, etc.
- `SignalQualityTests` reimplements `classifyRSSI()`, SNR functions
- `WiFiAnalyzerTests` reimplements channel classification
- `UtilitiesTests` reimplements format functions

This is testing the test code, not the production code.

## Implementation Plan

### Phase 1: Add Public Modifiers to All Types
Add `public` keyword to all types, properties, methods, and functions listed above.

**Files to modify:**
1. Sources/NetworkStatus.swift
2. Sources/AppConstants.swift
3. Sources/Preferences.swift
4. Sources/Logger.swift
5. Sources/Utilities.swift
6. Sources/HistoryStore.swift
7. Sources/NotificationManager.swift
8. Sources/NetworkMonitor.swift

10. Sources/WiFiAnalyzer.swift
11. Sources/IssueAnalyzer.swift
12. Sources/EventHooks.swift
13. Sources/ThreadSafe.swift
14. Sources/NetworkUtilities.swift
15. Sources/Protocols/TimeProvider.swift
16. Sources/Protocols/NetworkProvider.swift

### Phase 2: Add Missing Public Utility Functions
Some functions exist but are private. Either make them public or add public wrappers:

- Quality score calculation
- Signal quality classification (RSSI to SignalQuality)
- Channel band classification
- DFS channel detection
- PHY mode classification

### Phase 3: Update Tests to Use Production Code
After Phase 1, update test files to:
1. Remove private helper reimplementations
2. Call actual production functions
3. Test real behavior, not mirrors

**Test files to update:**
- QualityScoreTests.swift - use actual scoring functions
- SignalQualityTests.swift - use actual signal classification
- WiFiAnalyzerTests.swift - use actual WiFi utilities
- UtilitiesTests.swift - use actual format/emoji functions
- LoggerTests.swift - use actual Logger

### Phase 4: Validate
1. Run `swift build` to ensure no compilation errors
2. Run `swift test` to ensure tests pass
3. Run `swiftlint` to check for issues
